# YOLO001-B1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved `YOLO001-B1` label-free Small-track submission battery, deterministically build and hash all eight intended ZIPs, and stop at a Git-custodied `B1 CLOSED / UNSCORED` state before any B1 Codabench score is observed.

**Architecture:** Add a separate `aimo_interp_yolo` package beside the existing infrastructure package. Pure protocol/seed/extraction/decision logic stays independent of PyTorch; the competition runtime lazily imports the pinned runtime libraries, loads the organizer-supplied Small-track model once per `are_robust(...)` batch, and performs isolated seeded sampling per problem. A deterministic battery builder vendors the YOLO package plus one member execution record into each self-contained ZIP, while separate custody and result-ledger modules preserve `protocol -> implementation -> ZIP SHA -> Codabench submission -> result` provenance.

**Tech Stack:** Python 3.11+, `uv`, `pytest`, Python standard library; competition runtime provides PyTorch 2.12.1, Transformers 5.13.0, Accelerate 1.13.0, and the offline Hugging Face cache. No new project dependency is added for torch/transformers; imports remain runtime-lazy so ordinary CI remains CPU/lightweight.

**Spec:** `docs/superpowers/specs/2026-09-04-yolo001-b1-design.md`, user-approved at Git commit `2d2c362c3ea3f3970379d0520a9d2fc393df7127`.

- Competition entry point remains exactly `are_robust(model_id: str, problems: list[str]) -> list[bool]`.
- Returned predictions must be native Python `bool`, preserve input order, and contain exactly one result per problem.
- B1 uses no official training data, public development labels for parameter choice, private labels, activations, learned classifier, batch-relative normalization, or within-battery leaderboard tuning.
- `RELEASE_REGISTRY.json` remains untouched and retains sole scientific-gate jurisdiction.
- Scientific preregistration/execution remain unauthorized throughout this plan.
- `YOLO001-B1` contains exactly six self-consistency probes plus `CTRL-T` and `CTRL-F` leaderboard diagnostic controls.
- Shared seed namespace is exactly `YOLO001-B1`.
- Exact organizer problem strings are hashed without normalization and used verbatim before the fixed prompt suffix.
- Sampling parameters are fixed by the approved spec: `do_sample=True`, `top_p=0.95`, `top_k=0`, `num_beams=1`, `repetition_penalty=1.0`, `max_new_tokens=2048`, `use_cache=True`, model/tokenizer EOS.
- Heuristic extraction failure is a classifier observation; infrastructure failure must propagate and must never become `False` silently.
- All self-consistency members use one shared inference implementation; member differences come only from manifest data.
- Controls must not load the model.
- Deterministic ZIP construction must reuse `aimo_interp_infra.packaging.build_submission` rather than introduce a second archive format.
- B1 artifacts are built from one implementation commit; changing executable bytes after closure creates a new execution object.
- `B1 CLOSED` occurs before the first B1 upload and requires `C_B1 = P && I && Z && H`.
- No B1 result row may exist before closure.
- Any score-informed change after B1 observation is B2 or another explicit later epoch, never a mutation of B1.
- The existing `LOCAL BASELINE REPRODUCTION = ENVIRONMENT_BLOCKED` observation remains historically true; the external Codabench baseline smoke is recorded separately, not rewritten into a local pass.
- This plan ends at `protocol_state=CLOSED`, derived `evaluation_state=UNSCORED`. Codabench upload is a later action.
